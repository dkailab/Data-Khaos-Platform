# PRD · PaaS 项目空间隔离

维护者 **dkailab** · P0 · v0.1 待评审

面向同一平台实例内协作的多个数据团队。用零售数仓和营销分析两个项目交付首版，组员可以切换项目，按各自角色查看、编辑或运行当前项目内的工作流和管道。首版验收覆盖项目组、数据源引用、任务定义、运行记录和执行入口。

## 产品问题

平台已有项目组、主项目、成员角色、资源绑定及数据权限。当前实现中，管道基于默认项目组校验，工作流业务日期触发对部分路径校验项目成员身份。用户加入多个项目后，项目选择、资源列表、历史记录及执行权限仍需通过同一套规则验证。沿用现有项目组作为产品里的项目空间。

## 角色与任务

| 场景 | 组长 | 开发者 | 使用者 |
| --- | --- | --- | --- |
| 选择已加入的项目并查看授权任务与运行记录 | 可 | 可 | 可 |
| 管理本组成员、分配已有角色、绑定数据源 | 可 | | |
| 创建或编辑任务，手动执行本组任务 | 可 | 可 | |
| 调度配置与区间补数 | 可 | 按本项目授予的调度能力 | |
| 调整其他项目的成员、资源和任务 | 需在目标项目拥有对应权限 | 同左 | 同左 |

矩阵描述首版角色模板。自定义角色以本项目生效的能力位为准。平台管理员可从管理入口管理项目归属及历史归档，平台管理员直接触发项目任务时也需通过任务数据访问边界。

## 用户流程

评审时可打开[项目空间交互原型](../../prd/project-workspace-prototype.html)，直接体验以下场景。

1. 登录进入数据开发，顶部选择器显示已加入且启用的项目。首次进入优先使用有效主项目。
2. 切换项目后，任务、数据源选择和运行记录按当前项目刷新。编辑页切换项目前提示处理未保存内容。
3. 组长在既有项目组管理页维护成员和数据源绑定。开发者创建任务后能查看运行 ID、状态和错误。具备调度能力的成员可按已有业务日期契约发起补数。
4. 无项目时显示加入项目的说明。项目无任务时展示空状态及有权限的创建入口。项目被禁用或成员被移除后，当前页面提示选择仍可访问的项目。

## 发布验收

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A1 | 多项目成员切换 | 零售开发者兼营销使用者在两个会话分别操作两个项目，各自保留项目和角色，资料与权限互不串用。 |
| A2 | 资源归属 | 从列表、详情、运行记录进入资源，均只显示该会话项目下授权的对象。 |
| A3 | 执行授权 | 使用者无法运行任务。开发者可运行其项目内任务，工作流引用其他项目管道或未绑定数据源时拒绝执行。 |
| A4 | 调度与补数 | 项目内调度、手工执行和补数仍能关联日期及运行 ID。成员撤权后，新请求被拦截。调度执行时重新校验项目和绑定。 |
| A5 | 存量与运维 | 可归属的存量任务继续运行，归属缺失或冲突进入管理员处置清单。权限服务不可用时返回可诊断错误，资源访问和执行保持关闭。 |

后续阶段覆盖租户生命周期、计算与存储资源隔离、网络、配额、开发生产双环境和跨项目共享。首版发布对外称「项目空间隔离」。实现以[功能设计与交接](project-workspace-design.md)为准。
