# Data Khaos 数据技术文件评审

1. 从[技术文件摘要](../../../docs/standards/README.md)选择相关编号、章节和附录。从[架构映射](../../../docs/standards/architecture.md)定位项目模块，再用当前代码、配置和测试核对。正式对接时查验对端执行版本及角色。缺少原文或实测证据时把结论标为待核对。
2. 按当前业务区分平台内部共享、NDI 跨域流通和 AI 数据集生产。对 NDI 请求标明调用方、提供方、赋码方及注册、上架、发现、交付各自的状态。内部资产 ID 与外部标识分开，BI 消费 PaaS 数据接口，JDBC SPI 用于访问数据存储。
3. 对 AI 数据集，识别版本、用途、类型、来源许可和内容模态。按 TC609-5-2025-02 核对格式，对照 TC609-5-2025-04 分别记录说明文档、数据质量和模型应用的证据、得分和结论。保留模型适配性门控和不适用指标的权重调整。缺失评测证据时保持未验证状态。
4. 输出一张可执行的映射表，列出文件编号及版本、条款、要求强度、适用角色、项目模块、实现状态、证据、缺口和验收用例。区分原文要求、资料性参考和项目选型。用真实请求、数据或运行报告说明已验证的范围。
